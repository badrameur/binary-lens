            THE METHOD

            A prediction you can explain.

            From labeled examples to inspectable decision trees.

            Labeled files→Numerical features→Decision trees→Score + explanation
            01 / REPRESENTATION

            Files become numbers

            The model does not receive a filename or a screenshot. The EMBER2024 extractor calculates a fixed vector of 2,568 numbers: file size, entropy, byte frequencies, string patterns, and PE metadata where available.

            For ELF files, PE-specific groups are zero-filled. ELF section and segment inspection is a separate source of information.

            02 / LEARNING

            Trees learn useful splits

            LightGBM learns from examples labeled benign or malicious. Each tree tests features against learned thresholds. Additional trees improve the training objective based on what the existing ensemble gets wrong.

            The resulting model is a collection of numerical rules. No GPU or language model is required to use it.

            03 / INFERENCE

            New file, same extraction

            The uploaded file goes through the same feature definitions and ordering as the training data. A Windows PE file uses the PE model; a Linux ELF file uses the ELF model. Their trees produce a raw score, then a sigmoid maps it into the 0–1 model score.

            This demo uses ≤ 0.2 for likely benign, ≥ 0.8 for likely malicious, and an uncertain range between them. Those boundaries are a product choice, not calibrated confidence guarantees.

            04 / EXPLANATION

            Account for the actual score

            LightGBM calculates SHAP feature contributions for each prediction. Starting with a baseline, contributions sum to the raw score. Positive contributions push toward malicious; negative contributions push toward benign.

            Contributions describe the model's calculation. They do not establish causation, actual runtime behavior, or the precise bytes that contain malware.

            What this project claims

            Static malware classification for PE and ELF files, with inspectable model contributions and separate structural observations. Six file categories can be inspected: EXE, DLL, SYS, ELF executable, SO, and KO. Evaluation coverage is reported separately.

            No uploaded code is run. Files are analyzed in a child process with size, memory, and time limits. This is resource isolation, not a hardened malware sandbox. There is no dynamic execution, unpacking, emulation, or general steganography detection.

            Pretrained models and feature extraction come from the public EMBER2024 research project. Our own training experiment and its measured results are kept separate from the pretrained models used by the app.

            How to read the numbers

            Precision

            Of files flagged as malicious, how many were labeled malicious?

            Recall

            Of labeled malware, how much did the classifier detect?

            False-positive rate

            Of benign files, how many were incorrectly flagged?

            Confusion matrix

            Counts of correct detections, missed malware, false alarms, and correct benign predictions.

            Benchmark labels can be imperfect. These results do not establish future performance, category-specific accuracy, or effectiveness against every packing technique.
